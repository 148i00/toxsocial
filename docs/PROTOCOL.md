# ToxSocial — 社交协议规范 v0.1（草案）

传输载体：Tox **好友消息**（`tox_friend_send_message`，类型 `TOX_MESSAGE_TYPE_NORMAL`）。
每条协议消息 = 文本前缀 `TSP/1 ` + JSON 信封（UTF-8）。
**硬限制：单条 ≤ 1372 字节（`TOX_MAX_MESSAGE_LENGTH`）**；普通非 `TSP/1 ` 前缀消息视为普通聊天，协议层忽略。

## 1. 信封格式

统一 JSON 对象，`t` 字段区分类型；所有 id 用 UUID v4（文本形式）；`a` 为作者公钥（64 hex，由 Tox 层保证真实来源）。

```json
// 帖子
{"v":1,"t":"post","id":"<uuid>","a":"<64hex>","ts":1720000000000,"text":"你好 Tox 世界"}

// 评论
{"v":1,"t":"comment","id":"<uuid>","a":"<64hex>","ts":1720000000000,"rt":"<post_id>","text":"+1"}

// 反应（点赞/表情）
{"v":1,"t":"reaction","id":"<uuid>","a":"<64hex>","ts":1720000000000,"rt":"<post_id>","e":"👍"}

// 资料卡（改名/头像时广播）
{"v":1,"t":"profile","a":"<64hex>","ts":1720000000000,"name":"alice","bio":"hi","avatar":"<sha256hex>","avatar_len":12345}

// 回补请求（好友上线时发送）
{"v":1,"t":"sync_req","a":"<64hex>","ts":1720000000000,"since":1720000000000}

// 回补应答：直接回发帖子/评论流
{"v":1,"t":"sync_posts","a":"<64hex>","ts":1720000000000,"items":[{...post...},{...comment...}]}

// M4 附件元数据（正文走 Tox 文件传输）
{"v":1,"t":"file_meta","id":"<uuid>","a":"<64hex>","ts":1720000000000,"name":"photo.png","size":204800,"sha256":"<hex>","file_transfer_id":7}
```

字段说明：
- `ts`：作者本地 Unix 毫秒。排序键；客户端同时记录 `received_at` 防时钟偏移（M4 再细化）。
- `rt`：reply target，评论/反应指向的帖子 id。
- 所有接收方必须按 `(id, a)` 幂等去重（`posts` 表唯一索引），重复消息静默丢弃。

## 2. 消息类型总表

| `t` | MVP | 语义 | 处理方 |
|---|---|---|---|
| `post` | ✓ | 发布帖子，fan-out 给所有好友 | FeedEngine |
| `comment` | ✓ | 评论某帖子 | FeedEngine |
| `reaction` | ✓ | 点赞/表情 | FeedEngine |
| `profile` | ✓ | 资料卡更新 | 好友表 |
| `sync_req` | — | 请求回补 | 回补模块 |
| `sync_posts` | — | 回补数据流 | 回补模块 |
| `file_meta` | — | 附件元数据 | 文件模块 |
| `ping`/`pong` | ✓ | 可选存活探测（Tox 已有在线状态，通常不需要） | — |

## 3. 发帖与时间线语义

- 发帖 = 对所有在线好友逐条发送 `post` 信封（fan-out）。
- 时间线 = 本地 `posts` 表中 `author ∈ 关注列表`（含自己）按 `ts DESC` 聚合。
- 评论/反应不直接进时间线，而是挂在帖子详情下（`parent_id` 查询）。
- 离线好友：MVP 阶段会丢失（见 §4），M4 回补解决。

## 4. 离线回补协议（M4，pull 模式）

动机：Tox 无服务器、不缓存，好友离线期间的帖子必须显式同步。

```
A(上线)                          B(好友，在线)
  │── sync_req {since: <A见过B帖子的最新ts>} ──►│
  │                                             │ 查询本地 posts(author=B) 
  │                                             │ where ts > since（限 N 条）
  │◄── sync_posts {items:[...]} ────────────────│
  │  去重入库 (id,a)，emit 事件                   │
```

- 触发时机：`friend_status → ONLINE` 时发送 `sync_req`；每次 `sync_posts` 后若仍有缺口可再发（按 ts 游标翻页）。
- 去重由 §1 幂等规则保证；回补与实时消息并发到达不冲突。

## 5. 大小限制与分片

- 单条信封序列化后必须 ≤ **1300 字节**（留安全余量给前缀和 UTF-8 多字节）。
- 纯文本帖子上限 1000 字符（约 3000B UTF-8 > 上限时，需分片或降级为附件）。
- **长文分片**（M4 备选方案）：`{"t":"post_chunk","pid":"<uuid>","n":0,"total":3,"part":"..."}`，接收方按 `pid` 聚合，全部到齐后组装成 Post。MVP 不做，直接限长。
- **附件**：正文走 Tox 文件传输（`tox_file_send`，自带加密 + 断点续传），先广播 `file_meta` 让接收方知道文件用途，文件收完（`file_recv_control` 完成回调）后按 `sha256` 校验并挂到帖子下。

## 6. 安全模型

- **来源真实性**：Tox friend message 只能来自直接好友（公钥配对加密），`a` 字段由 Tox 层隐式保证 —— 非好友无法伪造发帖者。MVP 不额外签名。
- **转发攻击**（M4 频道场景）：conference 消息可被群成员转发冒充。对策：信封增加
  `sig` 字段，对 `(t|id|a|ts|text)` 做 ed25519 签名（私钥即 Tox 密钥派生），接收方验签。
  此字段 v0.1 预留位置（`"sig":"<hex>"`，可选）。
- **隐私**：帖子仅广播给直接好友；频道内容对频道成员可见（群聊加密由 Tox 保证）。
  拉黑 = 删除好友 + 忽略其消息（无法阻止对方看到你广播的内容 —— 与推特"移除粉丝"同理）。
- **已知边界**：Tox 为实验性加密库（官方声明未经独立审计）；无前向保密（MVP 不承诺）。

## 7. 兼容性策略

- 版本字段 `v:1`；未知 `t` 类型静默忽略（前向兼容）。
- 消息以 `TSP/1 ` 开头才解析，保证与未来普通聊天功能互不干扰。
- 所有字段解析失败即丢弃并记日志（不 panic）。
